UAE Pass Authentication Flow

OAuth 2.0 Authorization Code Grant — End-to-End Workflow

User (Browser)
Frontend (React)
Backend (Express)
UAE Pass IDP
Database (PostgreSQL)
1
User

User Clicks "Sign in with UAE Pass"

On the Login page, the user clicks the UAE Pass sign-in button. This triggers a call from the frontend to the backend.

2
Frontend

Frontend Requests Authorization URL

GET /api/auth/uaepass/authorize — The React frontend calls the backend to get the UAE Pass authorization URL.

3
Backend

Backend Generates State & Authorization URL

The Express server generates a cryptographic state parameter (32-byte random hex), stores it in an in-memory map with a timestamp, and constructs the OAuth2 authorization URL with parameters: response_type=code, client_id, scope, state, redirect_uri, acr_values, ui_locales=en.

Returns { authUrl, state } to the frontend.

4
Frontend

Browser Redirects to UAE Pass

The frontend sets window.location.href = authUrl, redirecting the user's browser to the UAE Pass identity provider login page.

User authenticates on UAE Pass
5
UAE Pass IDP

User Authenticates via UAE Pass

The user completes authentication on the UAE Pass platform (biometric, smart pass, or other supported method). Upon success, UAE Pass redirects the browser back to the application's callback URL with code and state query parameters.

6
Backend

Callback: Validate State Parameter

GET /api/auth/uaepass/callback?code=...&state=... — The backend receives the callback, validates the state parameter against the stored map to prevent CSRF attacks, then deletes the state entry. Invalid or expired states redirect to /login?error=uaepass_invalid_state.

7
Backend

Token Exchange with UAE Pass

The backend sends a POST request to {baseUrl}/token with grant_type=authorization_code, code, redirect_uri, client_id, and client_secret. UAE Pass returns an access_token.

8
UAE Pass IDP

Fetch User Profile

Using the access_token, the backend calls GET {baseUrl}/userinfo with Authorization: Bearer {token}. UAE Pass returns the user's profile: uuid, sub, email, firstnameEN, lastnameEN, firstnameAR, lastnameAR, gender, mobile, nationalityEN, idn.

Account provisioning & session creation
9
Database

Account Lookup or Creation

The backend looks up the user by email in the users table. If no account exists, a new user is created with: the name from UAE Pass (firstnameEN + lastnameEN), email (or fallback {uuid}@uaepass.local), a random bcrypt-hashed password, role user, and KYC status pending. A free plan subscription is also created in user_subscriptions with initial credits.

10
Backend

Generate JWT Access Token

A short-lived JWT access token is generated (15-minute expiry) containing userId and role, signed with the application's JWT secret.

11
Database

Create Refresh Token

A secure refresh token (64-byte random hex) is generated, SHA-256 hashed, and stored in the refresh_tokens table with userId, expiresAt (30 days), userAgent, and ipAddress. The raw token is set as an HttpOnly, Secure, SameSite=Lax cookie scoped to /api/auth.

12
Frontend

Redirect to Application

The backend serves an HTML page with inline JavaScript that stores the JWT token, user data, and token expiry in localStorage, then redirects to /onboarding (if KYC is pending/submitted) or /app (if KYC is approved). The user is now fully authenticated.

Error Handling Flows

  • User denies consent on UAE Pass: Redirected to /login?error=uaepass_denied
  • Missing code/state in callback: Redirected to /login?error=uaepass_missing_params
  • Invalid or expired state: Redirected to /login?error=uaepass_invalid_state (state entries expire after 10 minutes)
  • Token exchange failure: Redirected to /login?error=uaepass_token_failed
  • User profile fetch failure: Redirected to /login?error=uaepass_userinfo_failed
  • localStorage write failure: Redirected to /login?error=uaepass_storage_failed
  • Any unhandled error: Redirected to /login?error=uaepass_callback_failed
