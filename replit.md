# AgentLabs AI Calling Platform

## Overview
AgentLabs is a multi-tenant SaaS platform designed for AI-powered bulk calling. It supports various AI engines, telephony providers, and payment gateways, enabling users to create and manage calling campaigns, utilize AI voice agents with knowledge bases, design conversation flows, and manage contacts. The platform aims to provide a comprehensive solution for businesses seeking to automate and optimize their outbound and inbound calling operations using advanced AI capabilities.

## System Architecture
The application follows a client-server architecture.
- **Frontend**: Built with React 18, Vite, TypeScript, TailwindCSS, and shadcn/ui for a modern and responsive user interface.
- **Backend**: Implemented using Node.js and Express 4.x, utilizing Drizzle ORM for database interactions.
- **Database**: PostgreSQL, with schema defined in `shared/schema.ts`.
- **UI/UX**: Features a modern design inspired by Google Workspace Studio and Microsoft 365, including hero sections, template cards, category filtering, stats overviews, and quick action panels. Visual elements like gradients and consistent spacing are used throughout.
- **Hybrid Navigation System**: Microsoft 365-inspired layout with a slim top bar (48px) for logo, notifications, and user menu, plus a collapsible side rail (56px collapsed, 240px expanded) for main navigation. Sidebar state persists in localStorage. Click-to-expand only (no hover behavior). Admin panel includes "Return to App" link.
- **Real-time Communication**: Employs WebSocket connections for real-time voice streaming.
- **Background Processing**: Schedulers handle campaign execution, billing, and cleanup tasks.
- **Modular Design**: Feature modules and engine integrations are organized within the `server/modules/` and `server/engines/` directories, respectively.
- **Department Management System**: Includes robust features for organizing agents and IVR configurations within departments, supported by a 3-step wizard (Phone Numbers > Departments > IVR Router) at `/app/departments/canvas`.
- **Knowledge Base & AI Intelligence**: Provides an integrated experience for managing knowledge base content, performing AI-powered topic analysis, and generating content, utilizing a folder-based navigation system. Supports "Knowledge Base Only" mode (`knowledgeBaseOnly` flag on agents) that restricts AI responses strictly to KB content and system prompt, preventing use of general training knowledge. This applies across both ElevenLabs and OpenAI Realtime engines. The Knowledge Base page (`/app/knowledge-base`) uses a "Professor" persona throughout its UI - branded as "Professor's Knowledge Library" with academic-themed labels (Study Materials, Library Capacity, Ask the Professor, Professor's Expertise Level, etc.). The `knowledgeBaseOnly` flag is auto-enabled when agents are assigned knowledge bases during creation.
- **Provider DID Marketplace**: Integrates a marketplace for browsing and renting DIDs from various carrier providers, with routing capabilities for outbound calling.

- **Bedrock + Polly Engine (RockCenter)**: New engine at `server/engines/twilio-bedrock-polly/` using AWS Bedrock (Claude 3.5 Sonnet) for AI and multi-provider TTS (AWS Polly or ElevenLabs), with Twilio telephony. Frontend at `/app/rock-center`. API at `/api/bedrock-polly/`. Turn-based: Twilio audio -> Whisper STT -> Bedrock AI -> TTS (Polly or ElevenLabs) -> Twilio. 58 Twilio-supported Polly Neural voices across 18 languages (including Danish). Multi-provider TTS: Agent `voiceProvider` field ('aws_polly' | 'elevenlabs') determines TTS routing. ElevenLabs uses pcm_16000 output with 16kHz→8kHz downsampling for Twilio mu-law. API key resolution: agent credential pool → env var fallback. ElevenLabs errors automatically fall back to AWS Polly synthesis. All paths (Twilio stream, browser simulator, IVR) support both providers.

- **Humanized Agent Speech**: SSML Humanizer utility at `server/engines/twilio-bedrock-polly/services/ssml-humanizer.ts` processes AI response text into intelligent SSML before Polly synthesis. Features: sentence-level prosody variation (greetings get warmer pitch, questions get rising intonation, empathetic statements get softer/slower delivery), natural pauses at punctuation (280ms between sentences, 350ms before questions, 180ms at commas, 400ms at ellipsis), and breathing breaks after longer responses. Used by both `audio-bridge.service.ts` (phone calls) and `browser-voice-stream.ts` (browser simulator). The Enterprise Framework system prompt in `bedrock-agent-factory.ts` enforces human conversational patterns: natural fillers, varied sentence openings, emotional mirroring, anti-robotic patterns (never say "assist", avoid corporate-speak), and short 1-3 sentence responses.

- **Deprock Department System**: Replicates the Department Management system but specifically for the Bedrock + Polly engine. Uses AWS Polly voices (46 neural voices across 17 languages) instead of OpenAI/ElevenLabs voices. Frontend pages at `/app/deprock` (management) and `/app/deprock/canvas` (3-step wizard). Backend API at `/api/deprock/`. Uses same DB tables as departments (`departments`, `departmentAgents`, `ivrConfigurations`) but separated by `engineType` column ('default' for Departments, 'bedrock-polly' for Deprock). Files: `client/src/pages/DeprockManagement.tsx`, `client/src/pages/DeprockCanvas.tsx`, `server/routes/deprock-routes.ts`.

- **Deprock IVR System (Enterprise-Grade)**: Full Twilio IVR implementation for the Bedrock+Polly engine at `server/engines/twilio-bedrock-polly/routes/ivr-webhooks.ts`. Routes: `/api/deprock/ivr/answer` (greeting + Gather), `/api/deprock/ivr/handle-language` (multi-language selection), `/api/deprock/ivr/handle-selection` (department selection → agent stream), `/api/deprock/ivr/fallback` (timeout handler). Features: dual-input (DTMF + speech recognition with number word parsing in 19 languages), configurable voice speed (0.5x-1.5x, default 0.92x for clarity) via SSML `<prosody rate>` for Polly and `speed` param for ElevenLabs, retry logic (3 attempts max), fallback department, language-aware prompts. Speed stored per-language in `languageOptions` JSONB as `speed` property. Both `/api/bedrock-polly/voice/incoming` and `/api/webhooks/twilio/incoming` detect Deprock IVR configs and redirect accordingly. IVR configs filtered by `engineType` to prevent cross-contamination between Department ('default') and Deprock ('bedrock-polly') IVR systems. Full translation coverage for 14 core languages (en, fr, it, zh, hi, ar, es, de, ja, ko, pt, ru, tr, ur) plus Nordic languages (nl, pl, sv, no, fi, da).

- **IVR Call Simulator with Live Voice Conversation**: Browser-based tool at `/app/call-simulator` for testing IVR flows and having real-time voice conversations with AI agents without making actual phone calls. Frontend at `client/src/pages/DeprockCallSimulator.tsx`. Backend WebSocket at `server/engines/twilio-bedrock-polly/routes/browser-voice-stream.ts` (path: `/api/voice-sim/stream`). Supports both Deprock (bedrock-polly) and Department (default) IVR configurations. Flow: IVR menu navigation with Polly TTS audio → agent connection → push-to-talk mic recording → Whisper STT → Bedrock Claude AI → Polly TTS → MP3 audio playback. Chat-like transcript display with processing stage indicators.

- **Outbound Canvas**: Wizard-based outbound campaign creation at `/app/outbound`. 6-step flow: Use Case Selection → Contact Selection → Caller ID (Phone Number) → AI Agent & Voice → Knowledge & Script → Review & Launch. Step 1 fetches 94+ flow templates from `/api/flow-automation/flow-templates` categorized by use case (Sales, Support, Collections, Healthcare, etc.) with search and category filtering. Selecting a use case auto-populates the call script and campaign name. Step 4 shows agent cards with AWS Polly neural voice details, latency indicators (~400ms), SSML humanization badges, and KB connection status. Step 5 integrates Knowledge Base selection (from `/api/rag-knowledge`), URL import for reference content, call script editing, Quick Add form templates, and KB-Only mode toggle. Campaign creation passes `knowledgeBaseIds` and `knowledgeBaseOnly` to the backend, which updates the agent's KB config before execution. Uses existing campaign infrastructure (`/api/campaigns`). Mobile-optimized with 100dvh layout, safe-area support, responsive grids. Frontend at `client/src/pages/OutboundCanvas.tsx`.

- **Contact Import System**: Multi-source contact import on the AllContacts page (`/app/campaigns` all contacts). Supports: CSV/Excel file upload with preview, vCard (.vcf) file import, Google Contacts (OAuth2 via People API), Microsoft Outlook/365 (OAuth2 via Graph API), HubSpot CRM, and Salesforce. Backend routes at `server/routes/contact-import-routes.ts` registered at `/api/contact-import/`. Frontend dialog at `client/src/components/ImportContactsDialog.tsx`. OAuth providers for Google Contacts and Microsoft Contacts added to `server/services/oauth-providers.ts`. All imports are automatically assigned to a default "Imported Contacts" campaign (auto-created per user). Max 10,000 contacts per import. Contacts are inserted using batch operations for scalability.

- **Live Call Monitoring System**: Real-time supervisor dashboard at `/app/live-monitoring` for monitoring all active calls (40+ simultaneous). Centralized Active Call Registry (`server/services/live-call-registry.ts`) tracks calls across all engines with EventEmitter pattern. WebSocket endpoint (`/ws/live-monitoring`) pushes real-time call state changes, transcript updates, and lifecycle events with role-based filtering (admin sees all, users see own calls). REST API at `/api/live-calls/` for fetching active calls, stats, and ending calls. Frontend dashboard (`client/src/pages/LiveMonitoring.tsx`) features call grid with search/filters, live stats, call detail panel with transcript streaming, and monitoring capabilities. Integrated into all telephony engines: Twilio-OpenAI, Twilio-Bedrock-Polly, Plivo-OpenAI, Plivo-ElevenLabs, and SIP.

- **Payment Gateways**: Stripe, Razorpay, PayPal, Paystack, MercadoPago.
- **Database**: Neon (for PostgreSQL hosting on Replit).
